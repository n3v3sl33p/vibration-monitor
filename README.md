# Мониторинг вибрации виртуального электродвигателя M1

Учебный проект по дисциплине «Программное и аппаратное обеспечение информационных систем». Источник — математическая модель одного условного датчика вибрации. Реальное оборудование не подключается, промышленная диагностика не выполняется.

## Запуск ЛР № 2

Требуются Python 3.11+ и [uv](https://docs.astral.sh/uv/).

```bash
git clone https://github.com/n3v3sl33p/vibration-monitor.git
cd vibration-monitor
uv sync --locked
uv run pytest -q
uv run streamlit run app.py --server.address 127.0.0.1
```

Открыть `http://127.0.0.1:8501`. Это локальный веб-интерфейс, не публичный сайт. После установки зависимостей для моделирования Интернет не нужен. Остановка сервера: Ctrl+C.

### Контрольная конфигурация

- A = (1; 0,5; 0,25), F = (0,05; 0,1; 0,4) Гц — контрольный пример из методички ЛР № 1, **не назначенный индивидуальный вариант** из таблицы ЛР № 2.
- Частота выборки 20 Гц, сеанс 60 с, 1200 отсчётов, seed 42, стандартное отклонение дискретного Gaussian-шума 0,1.
- Амплитуда в условных единицах; частоты учебные, не паспортные характеристики двигателя.
- АЦП: 12 бит, диапазон [−4; 4], 4096 уровней, округление к ближайшему уровню (точная середина — к чётному коду), учёт насыщения.
- Блок приёма 128 отсчётов, последний блок может быть короче. Время `t[n] = n/fs`, без ожидания реального времени.
- EMA по умолчанию: период 3, α = 0,5. Среди периодов 1, 3, 5, 9, 21 он дал минимальную MSE относительно известного сигнала без шума на контрольном сеансе. Это не универсальный оптимум.

Сценарии: `normal`, `impulse`, `amplitude`, `frequency`. По умолчанию интервал отклонения [20; 30) с. Единственный прямоугольный импульс начинается в 20 с, длится 0,1 с и добавляет 2 усл. ед. Амплитудный сценарий увеличивает гармоническую часть вдвое, не меняя шум. Частотный сценарий удваивает частоту первой гармоники с непрерывной фазой; после интервала частота восстанавливается, накопленная фаза сохраняется. Маска отмечает заданный интервал изменения частоты, а не все отличия формы от исходной фазы.

На графике эталонная маска генератора — **не результат обнаружения аномалий**. ML будет реализован в ЛР № 3. Признаки будут рассчитываться до EMA.

### Модули

| Файл | Назначение |
|---|---|
| `generator.py` | Параметры, гармоники, шум, сценарии и эталонная маска |
| `acquisition.py` | Выборка, квантование, буфер, `run_session` |
| `processing.py` | EMA с переносом состояния между блоками |
| `app.py` | Настройки, запуск, графики Plotly, таблица отсчётов |
| `tests/` | Алгоритмические проверки и тесты интерфейса Streamlit AppTest |

Данные находятся только в оперативной памяти (`SessionBuffer`, `st.session_state`); при завершении процесса теряются. Автосохранения на диск нет. Исследователь задаёт параметры, оператор запускает и просматривает сеанс. Это сценарные роли, а не учётные записи или разграничение доступа.
